    Things to check in the current RTL

    • Undriven reset inputs. In top.v, the sinus_gen instance has no .reset and the ask_demod instance has no .rst. The registers have no initial values, so a simulation stays at X until a reset pulse is applied. On the FPGA they power up as 0. Add a reset input and drive both explicitly.
    • Offset-binary table read as signed. sine.mem swings from 0000 to ffff around 8000, but rom_memory and sinus are signed [15:0]. Values at or above 8000 become negative and the wave folds. Subtract 16'h8000 after reading, or regenerate the table as two's complement. Use the Sine table format control to compare.
    • Symbol is not a whole number of carrier cycles. 400,000 clocks ÷ 9,216 clocks per cycle ≈ 43.4 cycles, so each symbol ends part-way through a cycle. See the timing calculator for the nearest whole-cycle value.
    • Absolute threshold. THRESHOLD = 100_000 is tiny next to the full-scale accumulator value (about 2×1014 for a 16-bit carrier over 400,000 clocks), so it behaves almost like acc > 0. It gives little noise margin.
    • No symbol synchronisation. The demodulator's counter starts when rst is released. Nothing aligns it to the edges of data_in, so a window can straddle two bits.
    • Phase-sensitive detection. Two separate sinus_gen instances must stay in phase. Use the phase offset control: at 90° the output of a 1-bit drops to zero, at 180° it flips sign. Correlating against both sine and cosine (I/Q) removes this dependence.
    This page is a behavioural model of the data path (carrier, gate, multiply, integrate, compare). The carrier is drawn with a few cycles per bit for readability; the real design uses about 43. Channel noise and the threshold percentage are teaching aids and are not in the RTL.
